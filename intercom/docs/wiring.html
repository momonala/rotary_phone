Halloween Doorbell Wiring

When the intercom rings, an ESP32 hears it through a PC817 optocoupler and has a DFPlayer Mini play a spooky track through a Bluetooth speaker's AUX input. Everything sits on one 7 × 9 cm perfboard.

Sketches in intercom/: intercom_ring is the doorbell; its BOOT button plays a track to check the audio path. ring_capture streams every edge on D23; run uv run intercom/tools/record_ring.py on the Mac to see one line per ring burst, or add -o FILE to save the edges.

Use DAC_L, DAC_R and GND for line-out, never SPK1/SPK2. SPK1 and SPK2 are the built-in amplifier's bridged output: neither side is ground, so wiring them to a jack shorts the amp through the cable's sleeve.

Telling the doors apart

Each door plays its own tune on the same green–white pair, identical on every press. Measured with ring_capture on 2026-10-31, three presses per door.

Wiring

  • Perfboard and modules drawn to scale (10 px = 1 mm), top view, placed as in the build photo. The jack, speaker and intercom are not to scale.
  • ESP32: 30-pin USB-C devkit lying on its side, USB to the left. VIN…EN run along the top edge, 3V3…D23 along the bottom. Wire by the silkscreen labels.
  • DFPlayer: rotated so the SD slot faces left. SPK2…VCC run along the top edge, IO1…BUSY along the bottom.
  • PC817: drawn with pins 1–2 on top, so the dot (pin 1) is top-right. Pins 1–2 are the LED (intercom side), pins 3–4 the transistor (ESP32 side).
  • Tags with the same name are one connection: 5 V to 5 V, GND to GND. Both DFPlayer GND pins are connected on the board.
  • Dashed box: the existing intercom. The optocoupler is the only link: light crosses between its two halves, no wire does.

SD card and behaviour

  • Card 16SCOPE, folder /01/: 001_scream, 002_very_superstitious, 003_seven_years_bad_luck, 004_this_is_halloween, 005_witch, 006_circus (all .mp3). Repo copy: intercom/media/01/.
  • Each ring plays a random track from that door's list in the sketch. The on-board BOOT button (GPIO0) plays one from either list, and power-up plays 005 to confirm the audio path.
  • The on-board blue LED (GPIO2) is on while a ring signal is seen: steady through each 1.5 s burst, off in the gaps. The red LED is power and always on.

Gotchas

  • GPIO6–11 belong to the flash chip; never use them. GPIO16/17 are free on a WROOM-32D (only WROVER boards use them for PSRAM).
  • If init prints dots forever: swap RX/TX first, then check the card is FAT32.
  • Many Bluetooth speakers switch off after 10–30 min of silence, and some need a button press to select AUX. Check before Halloween.
  • Hum or buzz: the ESP32 and speaker share a charger. Use separate ones.
  • BOOT plays but the doorbell doesn't: flash ring_capture, run uv run intercom/tools/record_ring.py and press the bell. Only idle … low samples 0 lines means nothing reaches the optocoupler: check the cable and joints to the green–white pair first (a bad cable was the cause once), then polarity. One line per press like burst at 3.20 s: 1545 ms, 1712 edges means detection works; 1712 edges is the apartment door, 1944 the building door.
  • Wrong door detected: record both doors with -o and compare against the table above.
  • Flashing: rotary_phone/tools/flash.sh targets the rotary phone's D1 Mini, not this ESP32. Use arduino-cli upload --fqbn esp32:esp32:esp32:UploadSpeed=115200 -p /dev/cu.usbserial-10 intercom/intercom_ring; at the default 921600 baud the chip stops responding mid-upload.
